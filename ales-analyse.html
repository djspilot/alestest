ALES - Manufacturing Pipeline Architectuur & ERP Integratie

Situatie: Een manufacturing analysis pipeline die STEP CAD bestanden verwerkt en geometrische data extraheert voor vergelijking met ERP/SpaceClaim data.

Huidig: Werkend op macOS met hardcoded paden.

Doel: Productie-ready op Windows binnen ALES om als shadow process naast het bestaande ERP systeem te draaien.

Data Flow Beschrijving (Links → Rechts)

📥 Input Laag (Links): Ruwe STEP CAD bestanden (ISO 10303-21 formaat) worden ingelezen. Ondersteunt zowel enkele bestanden als batch verwerking van hele folders.

🔧 Analyse Engine: De kern van de pipeline. Gebruikt CadQuery (gebaseerd op OpenCASCADE) voor geometrische berekeningen. Detecteert automatisch:
• Gaten - via cylindrische face analyse (holes_count)
• Zettingen - bends met radius en hoek (bends_count)
• ISO data - toleranties, passingen, oppervlakte afwerking
• Features - AAG topology graph voor complexe shapes

💾 Data Verwerking: Optimalisatie laag. Cache systeem (MD5 hash) voorkomt herberekening van ongewijzigde bestanden. SQLite database bewaart historie. FreeCAD genereert platte patronen (unfold) voor laser/snijmachines.

📊 ERP Vergelijking: Validatie laag. Leest ERP data uit Excel (ArtikelNr, ZetAantal, Snijgaten) en SpaceClaim XML exports. Matcht onderdelen via volume. Vergelijkt met ±5% tolerantie en flagt afwijkingen.

📤 Output Laag (Rechts): 4 parallelle outputs:
• PDF - Professionele rapporten voor mensen
• CSV - Machine-readable voor ERP import
• JSON - API formaat voor integratie
• Logs - Audit trail voor compliance

2. Technische Componenten Detail

🔧 STEP Processing Module WERKT ✓

Bestand: analysis/step_processing.py

Functie: Laadt STEP bestanden via CadQuery/OCP en extraheert geometrische data.

  • Gaten detectie via cylindrische face analyse
  • Bend detectie met radius en hoek berekening
  • Volumetrische en oppervlakte berekeningen
  • SVG visualisatie generatie

Windows Impact: Geen wijzigingen nodig - CadQuery werkt cross-platform.

📐 Sheet Metal Analysis WERKT ✓

Bestand: analysis/sheetmetal_analysis.py

Functie: Analyseert plaatwerk componenten voor dikte, bends, en profielen.

  • Dikte detectie uit parallelle planar faces
  • Profiel classificatie (koker, U-profiel, hoekprofiel)
  • Bend telling voor ERP kostencalculatie
  • Onderscheid gekocht vs gefabriceerd

Windows Impact: Geen wijzigingen nodig - pure geometrische analyse.

🗂️ ISO Standards Module WERKT ✓

Bestand: analysis/iso_standards.py

Functie: Implementeert Nederlandse/ISO maakstandaarden.

  • ISO 2768: Algemene toleranties (f/m/c/v klassen)
  • ISO 286: Passingen (H7/h6, etc.)
  • ISO 1302: Oppervlakteruwheid (Ra/Rz)
  • ISO 68-1: Metrische schroefdraden
  • EN 10025/573: Materiaal dichtheden

Windows Impact: Geen wijzigingen nodig - lookup tables en berekeningen.

📦 FreeCAD Unfold WIJZIGING NODIG ⚠

Bestand: analysis/freecad_unfold.py

Functie: Genereert platte patronen via FreeCAD SheetMetal workbench.

  • Automatische base face selectie
  • Multi-attempt unfold strategie
  • DXF export voor laser/snijmachines
  • Theoretische unfold als backup

Windows Impact: HARDGECODEERD MAC PAD in config.py moet worden vervangen door Windows pad detectie.

🔗 ERP Compare Tool WIJZIGING NODIG ⚠

Bestand: scripts/compare_erp.py

Functie: Vergelijkt pipeline analyse met ERP/SpaceClaim data.

  • Excel parsing (pandas) voor ERP data
  • XML parsing voor SpaceClaim exports
  • Volume matching voor assemblage onderdelen
  • Afwijkingsrapport generatie

Windows Impact: FREECAD_PYTHON pad moet worden aangepast voor Windows. Functionaliteit werkt al.

💾 Cache Manager OPTIMALISATIE NODIG ⚠

Bestanden: core/utils.py (cache functies)

Functie: Voorkomt herberekening via MD5 hash tracking.

  • File-based cache (.pipeline_cache.json)
  • Stage-based cache (.pipeline_cache/ directory)
  • Automatische invalidatie bij wijzigingen

Windows Impact: Paden werken via pathlib, maar consistentie tussen cache systemen kan beter.

3. Wat Moet Er Nog Gebeuren?

Kritieke Wijzigingen voor Windows

1 FreeCAD Pad Configuratie

Huidige situatie: Hardcoded macOS pad in meerdere bestanden.

# HUIDIG (config.py regel 17) freecad_path: str = "/opt/homebrew/Caskroom/freecad/1.0.2/FreeCAD.app" # OOK IN (compare_erp.py regel 33) FREECAD_PYTHON = "/opt/homebrew/Caskroom/freecad/1.0.2/FreeCAD.app/Contents/Resources/bin/python"

Oplossing: Implementeer pad detectie logica die werkt op Windows:

# NIEUW - Windows compatibel import os import sys def get_freecad_path(): # 1. Check omgevingsvariabele (preferred voor ALES) env_path = os.environ.get("FREECAD_PATH") if env_path: return env_path # 2. Windows standaard locaties if sys.platform == "win32": windows_paths = [ r"C:\Program Files\FreeCAD 1.0", r"C:\Program Files (x86)\FreeCAD 1.0", ] for path in windows_paths: if os.path.exists(path): return path # 3. macOS (bestaand gedrag) return "/opt/homebrew/Caskroom/freecad/1.0.2/FreeCAD.app"
2 Foutafhandeling & Logging

Probleem: Pipeline crasht bij corrupte STEP bestanden of ERP data mismatches.

Oplossing: Implementeer try/except blokken met logging naar bestanden:

  • !Try/except rondom STEP loading - log corrupte bestanden
  • !Try/except voor Excel parsing - log formaat errors
  • !Try/except voor FreeCAD unfold - log geometry errors
  • !Logging naar dagelijkse files: logs/pipeline_2025_01_15.log

Belangrijk voor ALES: Pipeline moet onbemand uren kunnen draaien zonder menselijke interventie.

3 Dependency Management

Probleem: requirements.txt heeft geen gepinde versies.

# HUIDIG - niet reproduceerbaar cadquery>=2.4.0 cadquery-ocp numpy pymupdf # NODIG voor ALES - reproduceerbaar cadquery==2.4.0 cadquery-ocp==7.7.2 numpy==1.24.3 pandas==2.0.3 pymupdf==1.23.5 openpyxl==3.1.2
4 Input Validatie & Security
  • !Bestandsgrootte limiet: max 500MB per STEP file
  • !Pad sanitizatie: voorkom directory traversal attacks
  • !STEP formaat validatie: check header (ISO-10303-21)
  • !ERP schema validatie: verplichte kolommen check

4. ERP Integratie bij ALES

Huidige ERP Workflow bij ALES

De pipeline moet als shadow process naast het bestaande ERP systeem draaien zonder de hoofdprocessen te verstoren.

Huidige Situatie (SpaceClaim)

flowchart LR A[CAD Designer] --> B[SpaceClaim] B --> C[Manual Export] C --> D[Excel/XML] D --> E[ERP System] style A fill:#f5f5f5,stroke:#000000 style B fill:#ffffff,stroke:#000000 style C fill:#ffcccc,stroke:#000000 style D fill:#f5f5f5,stroke:#000000 style E fill:#ffffff,stroke:#000000

Probleem: Handmatige export uit SpaceClaim is tijdrovend en foutgevoelig.

Toekomstige Situatie (met Pipeline)

flowchart LR A[CAD Designer] --> B[STEP Export] B --> C[Pipeline] C --> D[Automatische Analyse] D --> E[Afwijkings Check] E -->|OK| F[ERP System] E -->|Afwijking| G[Review Queue] style A fill:#f5f5f5,stroke:#000000 style B fill:#ffffff,stroke:#000000 style C fill:#ccffcc,stroke:#000000 style D fill:#ccffcc,stroke:#000000 style E fill:#ffffcc,stroke:#000000 style F fill:#ffffff,stroke:#000000 style G fill:#ffcccc,stroke:#000000

Voordeel: Automatische validatie vangt afwijkingen op voordat ze in ERP komen.

Vereisten voor ALES ERP Integratie

1
Input Folder Monitoring
De pipeline moet een specifieke ALES input folder scannen op nieuwe STEP bestanden. Bijvoorbeeld: S:\ALES\CAD_Input\
2
ERP Data Matching
Match pipeline resultaten met ALES ERP data via ArtikelNr. ERP levert Excel met kolommen: ArtikelNr, ZetAantal, Snijgaten, Dikte, etc.
3
Tolerantie Checks
Vergelijk met ±5% tolerantie (afwijkend) of ±1 stuk (counts). Bij grote afwijkingen: flag voor handmatige review.
4
Output naar ALES Systemen
Genereer 3 outputs: (1) PDF rapport voor mensen, (2) CSV voor ERP import, (3) JSON voor API integratie.
5
Logging & Audit Trail
Log alle verwerkingen voor compliance. Bewaar hashes van STEP bestanden voor traceability.

5. Implementatie Roadmap voor ALES

Fase 1: Windows Voorbereiding (Week 1)

  • FreeCAD 1.0 installeren op ALES Windows Server
  • FREECAD_PATH omgevingsvariabele instellen in System Properties
  • Python 3.10+ installeren en toevoegen aan PATH
  • Git repository clonen naar C:\ALES\pipeline\
  • Netwerk toegang regelen voor input/output folders

Fase 2: Code Migratie (Week 1-2)

  • config.py aanpassen: Windows pad detectie implementeren
  • compare_erp.py aanpassen: FREECAD_PYTHON pad voor Windows
  • Alle pad operaties omzetten naar pathlib (cross-platform)
  • requirements.txt versies pinnen voor reproduceerbaarheid
  • Test run op 1 representatief ALES STEP bestand

Fase 3: Stabiliteit & Error Handling (Week 2-3)

  • Error handling toevoegen: try/except rondom alle I/O operaties
  • Logging implementeren: dagelijkse logfiles in logs/
  • Input validatie: bestandsgrootte limieten, pad sanitizatie
  • Batch processing testen met 10-20 ALES onderdelen
  • Vergelijking met SpaceClaim: handmatige validatie

Fase 4: ERP Integratie & Productie (Week 4)

  • Input folder koppelen aan ALES CAD export workflow
  • ERP Excel formaat afstemmen met ALES ERP team
  • Tolerantie thresholds finetunen op basis van tests
  • Documentatie schrijven: installatie, configuratie, troubleshooting
  • Overdracht aan ALES ERP team met training

6. Samenvatting

Conclusie: De pipeline is functioneel en goed gestructureerd, maar momenteel macOS-gecentreerd.

Voor ALES Windows productie moeten we:

  1. FreeCAD paden aanpassen (1 dag werk)
  2. Error handling toevoegen voor onbemeden operatie (2 dagen)
  3. Dependencies pinnen voor reproduceerbaarheid (0.5 dag)
  4. ERP data mapping afstemmen met ALES (1 dag)
  5. Testen & valideren met ALES dataset (2-3 dagen)

Totale inspanning: ~1 week ontwikkeling + 1 week testing/integratie

Risico's: Laag - de meeste componenten werken al, alleen configuratie en error handling moeten worden aangepast.
